### Browser findings and correction

The initial full Firefox run finished with 85 passed and two failures:

1. The two-profile Today’s Review test expected a generated Study checkpoint to
   clear automatically after the last answer. `static/script.js` explicitly
   excludes transient generated practice from automatic Study completion; the
   current workflow and manual require **Finish Review**. The test now verifies
   that the checkpoint still exists and completion is false after saving the
   answer, clicks Finish Review, then requires server-confirmed completion and
   checkpoint removal. It retains the cross-profile/shared-schedule assertions.
   No production behavior changed and no assertion was removed to hide a defect.
2. The mastery/recovery accessibility case failed in the initial run but passed
   in both focused runs without changing its assertions or production UI. The
   full-suite rerun also passed all 87 cases. This was not reproduced as a product
   defect; retain the case and monitor any recurrence rather than weakening it.

A focused run inside the restricted sandbox could not create loopback sockets.
It was rerun with the required local socket permission. Native frozen smoke
needed the same permission. These environment errors were not product failures.

The exact release commit does not exist yet. All six native targets require new
frozen-commit builds, OCR acceptance, desktop UAT, final-package checks, and
recorded hashes before publication. Windows/macOS/Ubuntu/Omarchy native behavior
was not inferred from Fedora. Final Fedora binaries must also be rebuilt despite
the successful preflight. Clean-machine screenshot/scanned-PDF OCR and normal
Explorer/Finder/desktop launch checks remain native release-execution gates.

and logs intentionally injected failure paths while still passing. Cleanup of
those test warnings is a non-blocking follow-up. Optional PDF generation, more
focused videos, and presentation polish are not release blockers. No live
dependency-vulnerability scan was performed; `pip check` establishes environment
consistency only, and the existing scheduled dependency audit remains separate.

No application source, APP_VERSION, release metadata, support assets, screenshot,
audio, or video was changed. No commit, push, merge, tag, or publication was
performed in this preparation pass.
