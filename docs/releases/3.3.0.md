# DLMS 3.3.0 draft release notes

**Status: unreleased development target, pending release review.**
The latest published release is [DLMS 3.2.2](https://github.com/drakahari/DLMS_next/releases/tag/v3.2.2),
verified through GitHub on October 2, 2026. These notes describe the application at `57d536f9bb20` on
`develop/3.3.0`. The owner accepted its Ubuntu 24.04 package; this is not an
announcement of public publication or acceptance of every native target.
See the [release review checklist](3.3.0-RELEASE-CHECKLIST.md) for validation
evidence and outstanding work.

## Current learner workflows

- A calmer **Study next** dashboard, compact continuation and independent Study
  History/Exam History shortcuts; eligible **More review options** remain beside plans.
- Durable Study sessions preserve first outcomes, corrections and observed
  assistance. **Finish Review** confirms saved coverage, including wrong answers.
  Pending saves and expired-token recovery retain response identity.
- Optional **Exam Plans** use exact folders intersected with Learning Scope,
  selected study days, a saved calendar timezone and honest workload estimates.
- **Mark for review** supports separate focused text-choice/matching practice and
  text-choice Anki export without clearing saved marks.
- **My Certifications** and **Training library** support any issuer, independent
  badge/certificate evidence, renewal history and approximate goals. Exact
  hours/minutes, estimated/submitted/accepted credit and the three independent
  dates remain distinct. AI matching is manual copy/open/paste, not issuer approval.
- **26 manual themes** and unified **Layout & navigation** preserve independent
  visibility choices, scoped restores and certification display preferences.
- Restore validates imported SQLite schema programs before writes; backup
  publication is collision-safe and requires hard-link support. Reduced-round
  matching Exams now save their validated round results consistently.

Read the [current manual](../user-manual/README.md) and its
[coverage checklist](../user-manual/UPDATE-COVERAGE-3.3.0.md) for task guidance,
compatibility limits and source evidence.

## Existing adapted Ethereal theme

Choose **Ethereal** in **Settings → Appearance** or the shared theme picker.
This Omarchy-inspired appearance combines midnight-blue surfaces, peach text,
and lavender accents. Reading text and form controls use local system sans-serif
fonts, with restrained monospace headings. No Omarchy installation, companion
plugin, downloaded font, or network connection is required.

Ethereal includes visible keyboard focus and a pale selection highlight with
dark selected text, including form fields and study content. Theme selection
persists through the existing settings system and applies to shared application
pages and generated quiz pages served by DLMS.

**Purple & Gold remains the default.** Dark, Light, and Maroon & Gold remain
available alongside Ethereal and the additional palettes. The original five
choices retain their established appearance; Ethereal is an adaptation, not a
reproduction of all upstream assets.

## Ethereal presentation refinements

- The shared sidebar uses more compact spacing, quieter section labels and
  dividers, and a narrow active-page indicator. It retains the existing links,
  actions, customization, visibility rules, and keyboard controls. Long labels
  wrap, and the mobile navigation can scroll to its controls.
- Dashboard and Study Packs headings are smaller and header spacing is reduced,
  while titles and supporting text remain readable. This also covers the
  Study Packs Other Studies view.
- Dashboard card borders and decoration are softer so Study next and its
  primary actions receive more emphasis. Every card, action, status, and
  navigation destination remains available.
- Study Packs keeps its expandable content, dataset tables, filters, and forms.
  The refinements apply only while Ethereal is selected.

## Compatibility and upgrade scope

Current data uses **schema 10**. Additive migrations support durable Study,
plans, marks and certifications; legacy shared certification dates stay preserved
and unclassified rather than being guessed. Planning deadline, recorded renewal
deadline and expiration are separate. Existing exact durations and credit remain.
Older application writers refuse an upgraded database. Replacing the binary alone
does not reverse a migration: rollback requires a verified pre-upgrade backup and
the compatible application, losing later changes. Restore replaces rather than merges.
Dependency/security changes are recorded in the canonical requirements and audit
remediation documentation; this is no longer a presentation-only release.

The intended native target matrix remains Fedora 44, Ubuntu 24.04 and 26.04,
Omarchy Quattro (all x86-64), Windows 11 x86-64, and macOS Apple Silicon.
Ethereal has no operating-system-specific requirement. Actual rendering varies
with system fonts, browser controls, and display settings. Available visual and
browser evidence is from Fedora 44 and Firefox; it does not establish acceptance
on the other targets, Safari, Chromium/Chrome, or physical mobile devices.

Keyboard, responsive, selection, and native Firefox 200% zoom checks provide
focused accessibility evidence, not a complete accessibility conformance audit.
Screen readers, forced colors, OS scaling, and other browser/platform combinations
still require review. The owner-accepted Ubuntu 24.04 package checkpoint above
does not qualify native Windows/macOS, other target binaries or AppImages. Prior
3.2.2 package results do not qualify new artifacts.

Before evaluating an upgrade, retain a backup outside the live data directory
and test restoration with an isolated copy. Native build, OCR, desktop launch,
shutdown/restart, package integrity, and upgrade checks must run against the
exact frozen 3.3.0 artifacts. The optional AppImage requires its own acceptance
on the named Linux hosts and remains separate from the six native packages.

Historical release notes and acceptance records remain unchanged.
