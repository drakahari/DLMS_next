# DLMS 3.3.1 maintenance candidate — unpublished

This source prepares a coordinated original/browser and Desktop maintenance
baseline. It is not a published release, installation instruction or approval
to update a production server. Current public stable remains original 3.3.0;
Desktop public previews remain Windows 2.2 and Linux/Mac 2.1.

## Scope and compatibility

Canonical starting source is `608c06252b788dcf8e02f58cb06893eaadcb5299`, unchanged
from the parity audit after fetching main. It already includes hotspot import
and safe rebuild, unchanged Study Resume preservation, selected missed-question
Anki exports, Marked/bundle navigation, exact selected AI copying and failure
feedback, import/restore hardening, and the later Avery Return/duplex templates.
The new correction separates certificate preview from attachment download.

View certificate now displays PNG/JPEG/WebP and a bounded image of one PDF page
at a time inside the application. Original PDFs remain download-only; raw PDF
embedding, native file dispatch, global file associations and origin policies
are unchanged. Download certificate explicitly saves the original using the
browser or Desktop Save As. Errors retain certification/training records.
The reported Omarchy installed build/file type and actual native behavior still
require the focused [platform handoff](3.3.1-native-handoffs.md).

Database schema **12**, full backup format **1**, portable quiz export format
**2** (supported format-1 imports retained), and Content/Study Pack schema **1**
are unchanged. There is no new migration or historical recovery tool.
Desktop journals/browser state are not cross-edition synchronization material.

## Version and source identity

All newly built application editions report **3.3.1**. Desktop remains
**Preview 1 candidate**, with platform release identifiers
`linux-331-preview1-candidate`, `windows-331-preview1-candidate`, and
`macos-331-preview1-candidate`. The original is a maintenance candidate until
its required native gates and owner review pass. No older binary is renamed.

The shared application version appears in the application UI and exports.
Desktop About additionally shows its host release, platform, exact source/build
and active mode. Windows Installer AppVersion uses BackendVersion=3.3.1 on
the preview-materials path; the host/installer revision remains separate.
Mac app/DMG metadata follows the canonical version. Expanded Mac provenance
is separate from the strict public About metadata. Clean builds record their
actual commit; any future overlay must retain an exact patch/snapshot identity.

Windows Preview 2.2 installer improvements are incorporated from its exact
published source supplement (archive SHA-256
`b8f05ff78c4b6ba27bdbe00b93b4e5151dc763f7695ff68f3f5a70b8850ad624`).
Its historical source/acceptance record is preserved; new native installer
qualification is still required. Accepted Qt/Mac standard printing, Windows
original-request printing and source/notice obligations remain in the baseline.

## Packages and remaining acceptance

Rebuild all five original packages (Fedora44, Ubuntu24.04, Ubuntu26.04,
Windows11 x86-64 and macOS arm64) because their shared code/version changes.
Rebuild Linux, Windows and Mac Desktop candidates because their bundled Local
application/version changes. Linux produces both a managed one-folder candidate
and standalone AppImage from the same verified payload, with different launch
and storage contracts. No original Omarchy package or Intel Mac is newly promised.

Native qualification does not transfer between operating systems. Existing
physical paper/alignment/duplex, signing/notarization, malicious same-user Mac
process and accessibility limits remain separately recorded. Reuse unchanged
acceptance only through verified relevant-input correspondence. Certificate
preview and new packaging/version behavior require new focused checks.

Read the [native build handoffs](3.3.1-native-handoffs.md) and separate
[installation/rollback proposals](3.3.1-installation-plans.md). No public download
URL or final release claim should be created until owner approval.
