## Source assessment

The branch is three commits beyond the v3.2.1 commit
`d3c9e944b5196f940b24373bf4690519d07223d0`. The changes are learning
review performance/error-response hardening, repository-local SVG UI icons,
and theme-aware sidebar accents. No dependency, database migration, package
matrix, or CI workflow change was introduced by those commits. The 3.2.2
preparation aligns active version text and adds the optional, separately
maintained Omarchy companion link. Historical 3.2.1 records and older-version
compatibility fixtures remain unchanged.

`DLMS.spec` bundles the entire local `static` directory, which includes the
tracked `static/icons.svg`. The native runtime smoke gate now requests that
sprite and checks for its Settings symbol; the source test checks the spec,
sprite, and source-archive exclusion contract. Existing icon tests cover local
symbol references and decorative accessibility markup. Enabled Firefox tests
cover the four exposed themes, computed feature colors, sidebar/card alignment,
normal-state contrast against the sidebar gradient endpoints, Settings hover,
selected color, and keyboard traversal. Fedora 44/Firefox human visual review
of the icon work was reported by the owner.

The current GitHub issue and Project state could not be independently read:
the available `gh` authentication is invalid and the Project page is not
accessible through the available read-only web access. The historical 3.2.1
readiness record identifies native icon acceptance as release-execution work;
it does not establish the current 3.2.2 roadmap state. The owner should
reconcile live issues and the roadmap before source freeze.

## Boundary to release execution

Passing source tests qualifies the reviewed source for owner review; it does
not accept native packages or an AppImage. The owner must produce a clean,
committed frozen SHA before invoking the native orchestrator. Native builds,
exact-artifact smoke and desktop acceptance, optional AppImage acceptance,
checksums, GitHub publication, and downloaded-release checks remain required
during release execution as described in the
[3.2.2 checklist](3.2.2-RELEASE-CHECKLIST.md).

The final audit handoff records the full non-browser and enabled Firefox gate
results for this working tree. Hosted CI and the manual Firefox workflow still
need their normal run on the reviewed frozen commit.
