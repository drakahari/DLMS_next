# DLMS 3.2.1 release execution checklist

Prepared September 23, 2026. This is future execution guidance, not evidence that
any release artifact has been built or accepted. See the
[source readiness assessment](3.2.1-READINESS.md) and
[canonical verification procedure](../RELEASE_VERIFICATION.md).

## Before freeze

- Owner reviews the complete source/documentation diff and both quality audits.
- Confirm APP_VERSION 3.2.1, current Help/manual/support assets and passing full
  non-browser and enabled Firefox gates, plus `git diff --check`.
- Owner commits and publishes source through the normal review workflow. Record
  the final full 40-character commit SHA; all hosts must use that exact clean
  checkout. Any subsequent source change requires renewed validation and freeze.
- Preserve historical captures and package evidence. Never relabel an old binary.

## Native builds and acceptance after freeze

On each matching host, activate the locked native build environment and prepare
its native OCR bundle as described in [OCR packaging](../OCR_PACKAGING.md).
Use a fresh output directory and the frozen commit:

```text
python tools/build_native_release.py --target TARGET --expected-commit FULL_40_CHARACTER_RELEASE_COMMIT --expected-version 3.2.1
```

| Target | Required final package |
| --- | --- |
| `fedora44-x86_64` | `DLMS-3.2.1-fedora44-x86_64.tar.gz` |
| `ubuntu24.04-x86_64` | `DLMS-3.2.1-ubuntu24.04-x86_64.tar.gz` |
| `ubuntu26.04-x86_64` | `DLMS-3.2.1-ubuntu26.04-x86_64.tar.gz` |
| `omarchy-quattro-x86_64` | `DLMS-3.2.1-omarchy-quattro-x86_64.tar.gz` |
| `windows11-x86_64` | `DLMS-3.2.1-windows11-x86_64.zip` |
| `macos-arm64` | `DLMS-3.2.1-macos-arm64.zip` |

Require frozen OCR probe, artifact/version smoke, final-package verification and
native desktop UAT on every host. Exercise normal launch/browser dispatch,
shutdown/restart, Help, sample import, Study/Exam, matching/hotspot, representative
upgrade data in a disposable copy, backup/restore, screenshot OCR and scanned-PDF
OCR without relying on a system Tesseract installation. Preserve native logs,
environment/bundle provenance, exact source SHA and final archive SHA-256.

For [DLMS-145](https://github.com/drakahari/DLMS_next/issues/4), record Windows
Explorer and a fresh normal shortcut with the expected DLMS icon and no default
PyInstaller icon. On native macOS, record Finder and Dock appearance and no
regression from the existing artwork. Record icon-cache observations separately
from packaging defects. Human visual acceptance is required; only explicit owner
acceptance permits Done/issue closure. If a source defect is found, fix, validate,
refreeze and rebuild affected release artifacts consistently.

For an optional final AppImage, follow the [AppImage matrix](../APPIMAGE.md#compatibility-decision-and-release-artifact-acceptance-matrix):
build on the Ubuntu 24.04 baseline from the frozen commit, transfer identical
bytes to Fedora 44, both Ubuntu targets and Omarchy, and record image hash,
FUSE/extraction fallback, real desktop/browser/menu behavior, OCR/PDFium and
shutdown/restart. DLMS-144 remains complete; this qualifies the final artifact.
AppImage has a separate acceptance/checksum record from the six-package set.

## Assembly, publication and downloaded acceptance

Collect unchanged native-produced archives. Compare transfer hashes against each
native-host record; generate the canonical six-file `SHA256SUMS.txt` and run
`verify_release_package.py --complete-set --checksums` with all six archives as
documented in the canonical procedure. macOS ZIP roots contain `DLMS.app`,
`README.txt` and `sample_quiz.txt`; other targets use their versioned wrapper.

Owner controls tagging and GitHub publication after native acceptance. Upload the
six archives and their manifest; do not create an extra source ZIP. Keep evidence
outside the frozen checkout so recording results does not change the build SHA.
After assets are available, verify actual downloads against native-recorded
hashes, the manifest and trusted local release tag with
`tools/accept_downloaded_release.py --tag v3.2.1` and the explicit repository/asset.
Perform browser-download Finder/Gatekeeper and Explorer/SmartScreen acceptance on
the actual native hosts; CLI download cannot establish quarantine/Mark-of-the-Web
behavior. Record publication and downloaded acceptance separately.

Optional manual PDF generation, tutorial candidate listening/editorial approval
and later video publication are independent of the application release freeze.
