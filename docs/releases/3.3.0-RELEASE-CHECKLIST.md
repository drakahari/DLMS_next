## Owner and release execution gates

- [ ] Owner reviews Ethereal visuals, default/other themes, notes, and this diff.
- [ ] Owner reconciles approved scope and live roadmap status. This source review
  does not assert issue completion or change Project state.
- [ ] Complete outstanding accessibility checks: focus order/visibility,
  keyboard access to all actions, readable selection/status/error states,
  screen-reader labels, forced colors, and native 200% zoom on other browsers.
- [ ] Complete isolated upgrade/restore checks with representative older data;
  confirm content, media, history, analytics, settings, and theme persistence.
- [ ] Owner commits/pushes reviewed changes, selects a clean frozen SHA, and runs
  hosted CI and the normal manual Firefox workflow on that SHA. Rerun affected
  checks after changes; do not reuse results for different application code.
- [ ] Separately authorize and execute native builds on all six hosts using
  [Native Release Verification](../RELEASE_VERIFICATION.md) and
  [OCR Packaging](../OCR_PACKAGING.md). Record source SHA, native environment,
  exact artifact hashes, bundled resources, version metadata and native UAT.
- [ ] Verify final archive layouts/support files, complete package set and
  checksums. Confirm no test data, secrets, staging files or caches are included.
- [ ] If offering an AppImage, complete [its independent gates](../APPIMAGE.md).
- [ ] Owner accepts all evidence and updates draft/support wording before the
  final source freeze. Any source or bundled-document change after a build
  requires fresh artifacts from the newly frozen SHA.
- [ ] Only under separate owner authorization: tag/publish the accepted files,
  then verify downloads/checksums and native downloaded-release acceptance.

This handoff does not authorize or perform builds, commits, pushes, tags, or
publication. Passing the available source gates leaves the unchecked release
execution and owner gates outstanding.
