# DLMS 3.2.2 release execution checklist

This checklist starts after the [source readiness review](3.2.2-READINESS.md).
None of the build, publication, or downloaded-release gates below is complete
merely because source tests pass. Use [Native Release Verification](../RELEASE_VERIFICATION.md)
for detailed commands and host-specific acceptance.

1. Owner reviews the 3.2.2 source and documentation diff, commits the accepted
   changes, and identifies the exact clean frozen commit. Confirm
   `APP_VERSION = "3.2.2"`, the branch/commit, and the required source and
   hosted-CI test results. Build only from that commit.
2. On each named native host, prepare the locked build environment and OCR
   bundle, then run `tools/build_native_release.py` with the full frozen SHA,
   `--expected-version 3.2.2`, and the matching target. Inspect its package,
   checksum, acceptance record, native smoke, and desktop/OCR behavior. The
   six targets are `fedora44-x86_64`, `ubuntu24.04-x86_64`,
   `ubuntu26.04-x86_64`, `omarchy-quattro-x86_64`, `windows11-x86_64`, and
   `macos-arm64`.
3. Verify the exact six final packages as a complete set using
   `tools/verify_release_package.py`, including clean extraction and native
   smoke on the matching hosts. Generate and verify `SHA256SUMS.txt` from those
   accepted bytes. Do not rename an earlier build as 3.2.2.
4. If an experimental AppImage is offered, build it from the same frozen
   source on the chosen Linux baseline. Verify the final image bytes across
   the intended distributions and desktop/browser workflows. It remains an
   additional distro-neutral artifact, separate from the six native packages
   and from the Omarchy companion plugin.
5. After owner acceptance, tag and publish the accepted packages and checksums
   with the 3.2.2 release notes. GitHub supplies source archives; do not make
   a separate source ZIP.
6. Download the published release assets and verify checksums and launch
   behavior. Perform Windows and macOS browser-download and desktop checks on
   those downloaded bytes, then record final acceptance separately from this
   source review.
