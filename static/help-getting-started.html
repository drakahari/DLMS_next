Getting Started & Navigation

Find the right workspace, create practice, and decide what to do next.

Find your workspace

Use the sidebar for Dashboard, Quiz Library, Build Quiz, Study Packs, subject study areas, Exam History, Analytics, Learning Intelligence, My Certifications, Anki Tools, Settings, Content Packs, Image Study Editor, and Help. On smaller screens, open the same navigation with the menu button.

Read your dashboard

Study next highlights your plan or recommended practice. A response waiting to save takes priority: use Resolve Study saves or Finish saving Exam first. Workload and save warnings stay visible even when practice is ready. Open Why this suggestion? for the reason, coverage detail and estimate assumptions. Included questions reviewed describes coverage, not mastery. When other recommendations are available, open More review options for optional review across your Learning Scope. Due-question and concept review take precedence over broader Adaptive Study suggestions; these options may include material outside your plan. A browser-only Resume entry does not remove shared review suggestions. Resume keeps your unfinished batch; starting another review creates a separate quiz.

Continue studying keeps your Last regular quiz separate from generated practice. It appears after a response has been saved to DLMS. An unfinished review offers Resume; a finished review offers Open current quiz. A browser checkpoint can also exist before any response is saved. Two entries combine only when they identify the same unfinished Study session and unchanged questions.

Open Manage browser resume point for the separate Clear browser resume point action. Clearing removes only the named checkpoint in this browser. Saved Study progress can still offer Resume afterward, and another local checkpoint may appear. Answers waiting to save must be resolved first.

After a finished review, Last regular quiz offers Open current quiz; it does not ask you to resume completed work. Open Study details, or Manage browser resume point when a browser checkpoint exists, for saved times and recovery details.

Your activity contains Continue your quiz sequence and Latest Exam completed. The sequence uses your last regular quiz with a saved Study answer. It offers the next regular quiz in the same folder only after a saved Finish Review for unchanged content. While unfinished, use the existing Resume action above. The saved order is the folder’s Quiz Library order: change it with drag-and-drop or Up and Down. Generated focused practice does not replace the anchor, and reviewed quizzes are not skipped. Hidden, excluded or unavailable material stops the sequence with an explanation. At the end, use Choose another quiz; DLMS never jumps folders. Opening a suggested quiz earns no review credit. Latest Exam completed keeps its score and Review attempt link.

Resume entries show their quiz ID, question position and browser-saved time so generated quizzes with the same title remain distinguishable. Missing times or positions are labeled unavailable. Clearing a browser checkpoint and completing a saved Study review remain separate actions.

Use Study History for finished reviews and partial Study sessions. Use Exam History for saved Exam results and clearly labeled legacy Study results. Quick tools keeps your enabled shortcuts together. Results overview summarizes Exam scores and older saved Study results. Finished and partial Study reviews remain in Study History, separately from these scores. Open What is counted? for the distinction.

Personalize visible study areas

Open Settings → Layout & navigation, or use Customize navigation in the sidebar. Settings stays in the sidebar even when every dashboard card is hidden. IT, Law and Medical have independent Show on dashboard and Show in sidebar choices; Other Studies is sidebar only. Select Save layout & navigation to apply your choices. Hidden areas keep their content, progress, history and direct links.

See Layout & navigation Help for Hide from both, dashboard-only cards and the separate Restore controls.

A normal study workflow

For earned credentials, use My Certifications and Training library. Optional Exam Plans guide preparation; they do not record an earned credential.

What should I study right now? Start with Study next on the Dashboard. It combines the most useful current actions from due questions, topic needs, unfinished work, and existing study activity without creating another scoring system.
Choose a source: Build Quiz, PDF & Image Import, a Study Pack, or a subject workspace.
Generate or open a quiz and choose Study Mode for feedback or Exam Mode for a completed attempt.
Return to Study next for the recommended next action. Use Study History for saved Study sessions or Exam History for one saved result, Analytics for patterns, and Learning Intelligence when you want topic detail or a specific review method.
Export selected material to Anki or printable cards when you want additional review outside a quiz.

See Which review should I use? for a concise comparison of the available review options.

Reopen and stop the right edition

DLMS Desktop

Desktop opens its own window and manages the selected Local profile and backend. Reopen the same profile through its package launcher; do not use a guessed localhost URL in an external browser. Close the Desktop window normally, or use Shutdown DLMS in Local. Follow pending-save, download and transition messages rather than forcing termination. The browser-presence grace period below is not the Desktop close procedure.

In Server mode, Keep open is the default when Desktop cannot verify remote save state. Closing Desktop does not stop that server or delete results already saved there. Check that server's History if uncertain. Desktop remembers the last selected mode; an unavailable Server shows a connection problem and an explicit return to Local, never silent fallback.

Browser-based DLMS

The application/server process owns the data and your browser displays it. In loopback-only Local use, Shutdown DLMS stops it immediately. If browser-presence shutdown is enabled, closing its final page may stop it after a grace period of about five minutes. While it is still running, reopen the access URL printed by its launcher (normally http://127.0.0.1:9001/).

In explicitly hosted LAN/server mode, in-app shutdown and browser-presence shutdown are unavailable. Closing a browser does not stop that server; stop its process or service on the host.

Read the Desktop build and active dataset

On Linux Qt Desktop, open the compact Local or Server: [name] mode control and select About DLMS Desktop…. The read-only dialog shows the application version, bundled Local release, Desktop source/build, target/support, runtime versions and active profile/origin or Server name/origin. The Local build does not establish the deployed Server's version. Choose Close to return focus to the mode control. Other Desktop hosts use their release-specific menu arrangement; browser-based DLMS has no Qt mode-menu action.

Save a Desktop export

On Linux Qt Desktop, deliberately activate the page's export/download action. After the private download completes, native Save As identifies Save Local [profile] export or Save Server [origin] export. Navigate visibly to an ordinary owned folder, keep the format's extension and choose a new filename. Wait for Export saved: [path]; a web request/prepared message is not destination-save confirmation.

Repeat the page's action to export again. An existing name is refused with Export not saved, leaving the existing file unchanged; dismiss it and repeat with a different name. Marked questions' explicit Download Anki package fallback also opens native Save As. Cancel changes no destination and retains the private download; if the same page remains active, focus returns to its prior control. Report unusable focus rather than assuming success.

Managed storage, symbolic-link paths and unsafe destinations are refused. An unconfirmed publication can leave a complete file: inspect the chosen folder and retained evidence before retrying. Finish the operation before switching mode or closing. The last successful export folder is remembered for the specific Local dataset or Server identity. Browser-based DLMS uses browser download behavior, and other Desktop hosts follow their release-specific prompts. Local Save Backup As… follows the separate managed backup procedure.

Choose the download and find its data

Browser-based DLMS 3.3.0 is the stable release. Desktop is available as separate Linux, Windows and Apple Silicon Mac previews; use the official releases for current files, checksums and platform limitations. Source Help corrections do not update an already downloaded package.

Browser-edition data defaults differ from Desktop profiles. Linux Desktop AppImage preview data is under ${XDG_DATA_HOME:-$HOME/.local/share}/dlms-desktop-appimage-test/profiles/<profile>/; an existing per-user installation may retain ~/.local/share/dlms-desktop-pilot/profiles/<profile>/. Explicit roots/platforms differ. In Local Settings → Backup & Restore, check the named profile and expand location details instead of guessing a folder. In Server mode, data belongs to the configured server. Never point two editions at one live data root.

Install original DLMS on macOS

DLMS Desktop is a separate application with its own platform previews. This section describes the stable browser-based macOS package, not Desktop. Use the project release page for each edition's downloads, checksums and qualification limits.

The packaged macOS release is an Apple Silicon ZIP containing a native DLMS.app bundle.

Download and extract DLMS-3.3.0-macos-arm64.zip (original DLMS 3.3.0 release; not a DLMS Desktop package).
Drag DLMS.app into /Applications.
Open DLMS from Finder or Applications. DLMS starts locally and normally opens its browser interface.
If Gatekeeper blocks the app, which is not Developer ID-signed or notarized, where available Control-click DLMS.app, choose Open, and confirm. Otherwise open System Settings → Privacy & Security, choose Open Anyway, and confirm.
Architecture: The documented macOS release is for Apple Silicon (arm64), not Intel. Quarantine removal with xattr is a troubleshooting fallback, not a normal installation step.

Connect Desktop, or host browser-based DLMS

Desktop Server connection

From Local, open the compact mode menu, choose Configure Server…, enter the deployment's exact root URL and a visible name, then select the configured Server. The control/title shows the active mode and profile/server; inspect the full origin in its details. HTTPS is recommended. HTTP requires explicit exact-origin opt-in: neither a private IP nor a Tailscale subnet router guarantees encryption for the remaining HTTP hop or provides application authentication.

Local and Server have separate data and browser storage. Switching does not copy, merge, synchronize or replay work. Resolve Local pending saves/transactions before switching. Server Settings affects server data; return to Local for Local managed backup/reset controls. For uploads, see Desktop file selection and consent.

Browser-based hosting

Browser-based DLMS defaults to a loopback bind at 127.0.0.1:9001. Headless/SSH detection affects browser opening, not network binding. To host intentionally, launch it with --host 0.0.0.0 and open the host's actual reachable address in a client. 0.0.0.0 is a bind address, not a browser destination. This is not a Desktop connection command.

Hosting boundary: the captured browser application supplies no user-login system or TLS. Use only an appropriately firewalled trusted network; do not expose it directly to the public Internet.
