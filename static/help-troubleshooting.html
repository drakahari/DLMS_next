Troubleshooting

Common fixes for parsing, PDF, Content Pack, browser-cache, and data-location issues.

Import problems

Text questions do not parse correctly

Confirm the source has clear question boundaries, labeled choices, and a correct-answer marker. Check Settings → Parsing and use the Regex Cleanup reference for copied PDF artifacts.

Smart PDF says material needs Review

Review is intentional when a question references an exhibit/output that selectable text did not preserve, or when a record is structurally ambiguous. Repair the record manually or exclude it; do not invent missing source content.

Smart PDF cannot read the PDF

Smart PDF requires selectable text. Scanned/image-only PDFs require OCR before DLMS can parse them; OCR is not currently built into this importer.

Content Pack problems

Open Content Packs → Details. DLMS reports invalid manifests, unsafe/missing paths, duplicate IDs/terms, missing image references, licensing/source warnings, and runtime discovery conflicts. A failed validation should be fixed at the source rather than bypassed.

Browser/UI issues after replacing static files

If a CSS or JavaScript change appears not to take effect, use a hard refresh (Ctrl + Shift + R) so the browser reloads cached static assets.

Where is my data?

DLMS intentionally stores runtime data outside the executable so replacing or upgrading the application normally does not erase quizzes, history, source banks, Study Packs, or settings.

PlatformTypical default DLMS data folder
Linux~/.local/share/DLMS/
If XDG_DATA_HOME is set, DLMS uses that data location instead.
Windows%APPDATA%\DLMS
Usually C:\Users\<username>\AppData\Roaming\DLMS.
macOS~/Library/Application Support/DLMS/

If the QUIZAPP_DATA_DIR environment variable is set, that location overrides the normal platform default.

Typical contents include folders for quizzes, data, configuration, Content Packs, quiz-owned assets, Smart PDF drafts/banks, and module-specific runtime content.

Do not delete the application-data directory when replacing the executable unless you intentionally want to remove stored DLMS data. Back it up before resets, migrations, or manual file edits.
