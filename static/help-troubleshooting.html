Troubleshooting

Use the smallest correction that preserves your source material and saved work.

Study Pack ZIP will not install

Return to the validation results. Blocking errors must be corrected in the pack ZIP before installation. Warning-only packs require explicit confirmation. Do not paste arbitrary AI prose into the ZIP handoff; ask the provider to return a valid DLMS Study Pack ZIP and upload it through the Builder or Content Packs.

Smart PDF needs Review

Review is expected when selectable text is incomplete or structurally ambiguous. Repair the record from reliable source material or exclude it. Scanned/image-only PDFs need OCR before Smart PDF can use their text.

A study area is missing from the sidebar

Open Settings → Navigation and re-enable the area. This setting does not remove the area or its data; a saved direct URL also remains usable.

Backup, restore, or data concerns

Use Backup & Restore to create a portable backup before resets or major changes. If a restore is rejected or fails, do not delete active data to work around the message; verify that you selected a valid DLMS backup and keep the current data available until you have a known-good backup.

macOS app is blocked by Gatekeeper

First use the normal first-run choices: where available, Control-click /Applications/DLMS.app and choose Open, or use System Settings → Privacy & Security → Open Anyway after a blocked launch.

Only if those choices are unavailable, verify the downloaded ZIP against the release SHA256SUMS.txt, then run xattr -dr com.apple.quarantine /Applications/DLMS.app. This removes quarantine only from that DLMS app and should remain fallback troubleshooting rather than routine installation guidance.

Browser closed but DLMS is still running

Closing a browser only closes the interface; it does not stop the already-running DLMS process. Reopen the browser and visit http://127.0.0.1:9001/ to reconnect, and do not start another server copy. When you are finished, use Shutdown DLMS in the sidebar to fully exit.

If the local address no longer responds, confirm that the earlier DLMS process has stopped, then launch DLMS normally.

Browser or display problem

Refresh the page after an update. If a layout looks stale, close old DLMS tabs and reopen the local URL. On a LAN, confirm that you are using the exact address printed when DLMS started and that the network is trusted.
