Maintenance & Recovery

Maintain DLMS safely and protect the application-data directory before destructive operations.

Maintenance page

Maintenance centralizes operational cleanup and administrative actions. Use it deliberately; maintenance features can affect stored runtime data.

What “Rebuild All Quiz Pages” actually does

This maintenance command regenerates the HTML page wrapper for every registered quiz using the current DLMS quiz template. It is primarily a compatibility/UI refresh after an application upgrade.

It does

  • Read each quiz entry from the DLMS registry.
  • Use the quiz's existing ID, title, logo, exam timer, and associated JSON filename.
  • Run the current build_quiz_html() template for that quiz.
  • Overwrite/regenerate the quiz's generated HTML file in the quiz-pages folder.
  • Report how many quiz pages rebuilt successfully and which quiz IDs failed.

It does not

  • Change questions or answer choices.
  • Change correct answers or Study Mode explanations.
  • Rebuild the quiz JSON from the database.
  • Change quiz IDs or registry entries.
  • Delete or rewrite attempt/history records.
  • Repair missing or corrupt source quiz data.

When should I use it?

Use it after upgrading DLMS when existing quizzes were generated with an older page template and you want them to receive current interface behavior or template-level features. You normally do not need it just because you restarted DLMS.

Think of this as “re-render every saved quiz with the current DLMS quiz-page template,” not “recreate every quiz from scratch.” The underlying quiz content remains the same.
Because the rebuild uses each quiz's existing data/JSON reference, it is not a recovery tool for a missing or damaged quiz data file. Back up the DLMS application-data directory before broad maintenance operations.

Back up before major changes

DLMS stores runtime content outside the executable. On Linux the default is ~/.local/share/DLMS/ unless QUIZAPP_DATA_DIR overrides it. That separation is why replacing a binary normally preserves quizzes, source banks, Study Packs, settings, and history.

A simple Linux backup is:

tar -czf DLMS-backup.tar.gz -C ~/.local/share DLMS
Create a backup before release upgrades, reset/recovery operations, or any manual edits inside the application-data directory.

Upgrades

Replacing the application executable should not require deleting the application-data directory. Database initialization is designed to update the schema in place. If a release specifically requires a migration step, follow that release's instructions instead of manually clearing data.
